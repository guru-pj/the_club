🧩 THE CLUB — SERVICE CONFIGURATION REFERENCE

1. User Service
---------------

Dependencies:
  - spring-boot-starter-web
  - spring-boot-starter-data-jpa
  - spring-boot-starter-validation
  - mysql-connector-j
  - lombok (optional if used)
  - spring-boot-devtools (for dev environment)

Database Configuration:
  - spring.datasource.url=jdbc:mysql://localhost:3306/userdb
  - spring.datasource.username=root
  - spring.datasource.password=root
  - spring.jpa.hibernate.ddl-auto=update
  - spring.jpa.show-sql=true

Application Properties:
  - server.port=8081
  - spring.application.name=user-service


2. Auth Service
---------------

Dependencies:
  - spring-boot-starter-web
  - spring-boot-starter-security
  - spring-boot-starter-data-jpa
  - jjwt-api, jjwt-impl, jjwt-jackson (for JWT)
  - mysql-connector-j
  - lombok (optional)

Database Configuration:
  - spring.datasource.url=jdbc:mysql://localhost:3306/authdb
  - spring.datasource.username=root
  - spring.datasource.password=root
  - spring.jpa.hibernate.ddl-auto=update

Application Properties:
  - server.port=8082
  - spring.application.name=auth-service
  - jwt.secret=yourSecretKeyHere
  - jwt.expiration=3600000


3. Activity Service
-------------------

Dependencies:
  - spring-boot-starter-web
  - spring-boot-starter-data-jpa
  - postgresql
  - lombok (optional)

Database Configuration:
  - spring.datasource.url=jdbc:postgresql://localhost:5432/activitydb
  - spring.datasource.username=postgres
  - spring.datasource.password=postgres
  - spring.jpa.hibernate.ddl-auto=update

Application Properties:
  - server.port=8083
  - spring.application.name=activity-service


4. Gateway Service
------------------

Dependencies:
  - spring-cloud-starter-gateway
  - spring-cloud-starter-netflix-eureka-client

Application Properties:
  - server.port=8080
  - spring.application.name=gateway-service
  - spring.cloud.gateway.discovery.locator.enabled=true
  - spring.cloud.gateway.discovery.locator.lower-case-service-id=true
  - eureka.client.serviceUrl.defaultZone=http://localhost:8761/eureka


5. Discovery Service
--------------------

Dependencies:
  - spring-cloud-starter-netflix-eureka-server

Application Properties:
  - server.port=8761
  - spring.application.name=discovery-service
  - eureka.client.register-with-eureka=false
  - eureka.client.fetch-registry=false


6. Config Service
-----------------

Dependencies:
  - spring-cloud-config-server
  - spring-boot-starter-actuator

Application Properties:
  - server.port=8888
  - spring.application.name=config-service
  - spring.cloud.config.server.git.uri=https://your-repo-url.git
  - spring.cloud.config.server.git.clone-on-start=true

🏗️ DATABASE DEPLOYMENT LOCATIONS
================================

Below are the recommended database deployment setups for each service:

1️⃣ User Service
----------------
- Database: MySQL
- Recommended Run: **Docker Container**
- Reason: Easier to link with user-service container, consistent schema setup across environments.
- Local Access (if needed): 
  - Host: localhost
  - Port: 3306
  - Database: userdb
  - User: root
  - Password: root

2️⃣ Auth Service
----------------
- Database: MySQL
- Recommended Run: **Docker Container (same MySQL as User Service)**
- Reason: Both can share the same MySQL container with separate databases or schemas.
- Local Access (if needed):
  - Host: localhost
  - Port: 3306
  - Database: authdb
  - User: root
  - Password: root

3️⃣ Activity Service
--------------------
- Database: PostgreSQL
- Recommended Run: **Docker Container**
- Reason: Needed for Trino integration and consistency across environments.
- Local Access (if needed):
  - Host: localhost
  - Port: 5432
  - Database: activitydb
  - User: postgres
  - Password: postgres

4️⃣ Gateway Service
-------------------
- Database: None
- Depends On: **Discovery Service** & **Config Service**
- Recommended Run: **Docker Container** only (no DB needed).

5️⃣ Discovery Service
---------------------
- Database: None
- Recommended Run: **Docker Container** only (no DB needed).

6️⃣ Config Service
------------------
- Database: None
- Uses Git repo as configuration source.
- Recommended Run: **Docker Container** only.

7️⃣ Trino
----------
- Databases: MySQL + PostgreSQL (connectors)
- Recommended Run: **Docker Container**
- Reason: Trino runs as an intermediary query engine for analytics, not for data storage.
- Local Access:
  - Host: localhost
  - Port: 8085 (mapped from container)
  - Web UI: http://localhost:8085

🚀 STEP-BY-STEP GUIDE TO BUILD AND RUN THE CLUB SERVICES
========================================================

Follow these steps to build and run all services smoothly using Docker.

1️⃣ PREREQUISITES
-----------------
Make sure you have the following installed on your Mac:
- Docker Desktop (running)
- Java 17+ (preferably 21 or 25)
- Maven 3.9+
- Git

2️⃣ PROJECT STRUCTURE
----------------------
The folder layout should look like this:

the-club/
 ┣━ user-service/
 ┣━ auth-service/
 ┣━ activity-service/
 ┣━ gateway-service/
 ┣━ discovery-service/
 ┣━ config-service/
 ┣━ docker-compose.yml
 ┗━ (this reference file)

3️⃣ BUILD EACH SERVICE LOCALLY
-------------------------------
From the root of each service directory, run:

```bash
mvn clean package -DskipTests
```

This will generate a JAR file under `target/` (e.g., `user-service-0.0.1-SNAPSHOT.jar`).

4️⃣ BUILD DOCKER IMAGES
------------------------
After packaging all services, run this from the **project root**:

```bash
docker-compose build
```

This will build Docker images for:
- user-service
- auth-service
- activity-service
- gateway-service
- discovery-service
- config-service

5️⃣ START DATABASES FIRST (OPTIONAL STEP)
----------------------------------------
If you want to confirm your DB containers are running fine, you can start them first:

```bash
docker-compose up -d mysql postgres trino
```

Check containers using:
```bash
docker ps
```

6️⃣ START ALL SERVICES
----------------------
To bring up the full system:

```bash
docker-compose up -d
```

This starts everything in the background.
You can view logs with:
```bash
docker-compose logs -f
```

7️⃣ VERIFY SERVICES
-------------------
Once up, check the following URLs in your browser:

| Service | URL |
|----------|-----|
| User Service | http://localhost:8081 |
| Auth Service | http://localhost:8082 |
| Activity Service | http://localhost:8083 |
| Gateway Service | http://localhost:8080 |
| Discovery (Eureka) | http://localhost:8761 |
| Config Service | http://localhost:8888 |
| Trino Web UI | http://localhost:8085 |

8️⃣ STOP AND CLEAN UP
----------------------
To stop all running containers:

```bash
docker-compose down
```

To remove all volumes and networks (fresh start):

```bash
docker-compose down -v
```

🧩 PRO TIPS
------------
- You can use **pgAdmin** on Mac to view PostgreSQL data from Docker.
- Use **MySQL Workbench** or **DBeaver** to connect to MySQL inside Docker.
- If you modify `.properties` files, restart the specific service container using:
  ```bash
  docker-compose restart <service-name>
  ```
- To rebuild after code changes:
  ```bash
  docker-compose up -d --build
  ```

🎯 END RESULT
--------------
After completing these steps, your microservice ecosystem (The Club) will be fully operational with:
- Auto-discovery via Eureka
- Centralized config via Config Service
- API routing via Gateway
- DB interaction through MySQL/PostgreSQL/Trino
